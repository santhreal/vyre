# vyre-alloc-probe

Per-thread heap counters behind a `GlobalAlloc` wrapper. A binary installs
`ThreadAlloc` as its global allocator, opens a `Region` around the code under
budget, and reads the traffic that region charged to its own thread.

`cargo test` runs cases on a thread pool, so a process-wide counter charges one
case for every allocation the cases beside it made. The counters here are
thread-local, so a budget measures the code under test rather than the
schedule. Gross allocations and deallocations are reported alongside the net,
which separates churn from retention.

This crate depends on no vyre crate. The benchmark harness links it at run time
because a `[[bin]]` cannot reach a dev-dependency, and a driver suite links it
as a dev-dependency, without either reaching a test-only crate.

Not here: a second allocation counter, or any measurement that is not heap
traffic.
