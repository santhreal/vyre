# Vyre 0.7.0 / Weir 0.1.1 release notes

Release train: vyre 0.7.0 and weir 0.1.1. Both release groups move together.

Crates: vyre-driver-cuda@0.7.0 and vyre-driver-wgpu@0.7.0, alongside every other
publishable crate in the vyre group, plus weirflow@0.1.1 in the Weir group.

RC tags: vyre-v0.7.0-rc.1, weir-v0.1.1-rc.1, vyre-0.7.0-weir-0.1.1-rc.1.

Final tags: vyre-v0.7.0, weir-v0.1.1, vyre-0.7.0-weir-0.1.1.

Tag order: cut the three RC tags first, run the release gate against them, then cut
the three final tags. Every tag is product-scoped, so nothing in the release workflow
refers to a tag that could mean either the outer monorepo or the vyre crates.

This is one release. The work that had been staged as 0.6.6 is folded in: it could not
ship as a patch, because making its release gate pass required canonicalizing
eigenvector sign in the shared Jacobi body, and that changes the observable output of a
published op. The dataflow-import rename is the only source edit an upgrade requires,
and "Upgrading" below is the full table.

## What is in this release

**Device closures now say whether they converged.** A persistent-BFS closure that
exhausts its `max_iters` budget while still growing produces an under-approximated
frontier, and until now the device path returned that partial frontier with no way to
tell it apart from a real fixpoint. Every persistent-BFS program now writes a
`converged` output: one u32 word for the single-query programs, a per-query array for
the batch programs. The CPU reference carries the same signal, so device and reference
results are comparable flag-for-flag.

Two analyses consume it. A forward loan-issue or backward loan-use closure in vyre-libs
borrow checking that did not converge now fails the dispatch with a `Fix:` message,
because borrow-checking a truncated loan reachability set silently drops conflicts. The
optimizer's dispatched dead-code elimination does the same on both its direct and its
resident path: liveness is a reachability closure, so running DCE against a truncated one
deletes code that is live. That failure is a miscompile rather than a missed
optimization, which is why those paths refuse instead of degrading.

**Frontier density is available without a per-step round-trip.**
`persistent_bfs_with_density` and its batch counterparts declare one extra u32 output
holding the frontier popcount after each traversal step. A host reconstructs every
per-iteration density aggregate from that array plus the seed popcount. The base
programs are byte-for-byte unchanged, so callers that do not want telemetry pay
nothing.

**A host-loop fixpoint solver can move its loop onto the device without holding a
backend handle.** `dispatch_with_grid_sync_split_via_into` takes an opaque
single-launch dispatch closure instead of a `&dyn VyreBackend`. The split,
input-refresh, and convergence logic moved into one shared function, so the backend
entry and the closure entry run the same code and converge to identical output.

**The CPU reference interpreter no longer silently computes one query out of many.**
It inferred coverage from buffer shapes, distributing the dispatch only across
workgroup axes larger than one. A program fanning a `[256, 1, 1]` workgroup across
`grid.y`, which is how batched persistent BFS runs one query per block, collapsed to
`grid.y == 1` with no diagnostic. `DispatchConfig::dispatch_grid` states the real
per-axis grid and overrides shape inference.

**The raw-byte C syntax parser no longer under-counts tokens on large sources.** Its
sparse token compaction runs a block-total stage, one 1024-lane workgroup per block.
That stage's only sized buffer holds one word per block and its input arrives as a
resident device blob whose length the grid inference cannot read, so inference chose a
single workgroup for every source under a million tokens. Block 0 computed its total and
every later block kept a zero, which the compact stage then used to rank tokens: 4096,
8192 and 66560 semicolons all reported 2048 tokens, with no error. Both block-total
dispatches now state their grid.

**Fusing a narrow synchronizing kernel behind a wide one no longer produces an
intermittently wrong program.** The fused launch geometry is the axis-wise maximum over
the arms. For an arm whose invocations are independent that is only a launch-size
change; for an arm that synchronizes its workgroup or keeps state in workgroup memory it
changes the meaning of the arm, because such an arm guards its body for its own width
and the extra invocations then skip the guarded body and never reach the barrier the
working invocations wait on. Piping a 256-wide elementwise op into a 4-element prefix
scan produced a kernel that returned the wrong last lane on 49 dispatches out of 500 of
the same input. `fuse_programs` now refuses that batch with
`FusionError::WorkgroupGeometry`, naming the arm, both geometries, and what in the arm
makes the widening unsafe. Independent arms are still widened, and arms that already
agree on their workgroup still fuse even when both synchronize. If you hit the refusal,
dispatch that arm separately. A fused program also keeps `non_composable_with_self` as
the OR over its arms, which it used to reset to `false`.

**Two security advisories are cleared.** `crossbeam-epoch` moves 0.9.18 to 0.9.20 for
RUSTSEC-2026-0204, where the `fmt::Pointer` impl dereferenced the pointer it was
formatting, and `anyhow` moves 1.0.102 to 1.0.104 for RUSTSEC-2026-0190, where
`downcast_mut` after `Error::context` violated borrow rules. Both are patch-level moves
with no API change. `cargo deny check` is green on advisories, bans, licenses and
sources.

**A composite op can take a whole buffer.** An op could only receive scalars, so a
phase that indexes a table could not be split into its own composition, and the
composition-discipline gate ended up prescribing a split the pipeline refused to
compile. `Expr::BufferRef` names a buffer at a call site. It is not a value, has no
type, and is legal only as a call argument; an op signature declares such a parameter
as `buffer<u32>`. Inlining retargets the callee's loads, atomics and `BufLen` onto the
caller's buffer while keeping the callee's index expressions, so a callee that reads
`table[i]` really reads the caller's table. Scalar arguments behave exactly as before.
Wire format rev 5 carries the new tag, and the decoder still reads rev 4.

**The reference interpreter computed nothing for a composite op, and said it
succeeded.** `Expr::Call` was always dispatched to the op's registered CPU function,
but a composite op is defined by its IR body and registers no CPU function, so it
landed on a non-executable sentinel that clears the output buffer and returns. Any
differential using such an op was comparing against zeros. The interpreter now inlines
composite bodies before execution, so only intrinsics reach CPU dispatch, and reaching
the sentinel is a hard error naming the op.

**Typedef annotation is three ops instead of one monolith.**
`c11_annotate_typedef_names` carried every phase inline at 613 statement nodes against
a 200 budget, depth 20 against 6, and 37 loops against 8. Its three per-row phases are
now registered ops that take the node table and haystack as buffer references. The
calls inline before lowering, so the emitted kernel and the C parser's oracle parity
are unchanged.

**Positioned evidence can be filtered without losing presence.** The literal-set and
bounded-range suffix3 fused scans keep per-region presence complete for every pattern
while emitting match triples only above a supplied pattern-id boundary. Dense
admission-only rows no longer consume atomic counter capacity or readback bandwidth.

**Paged corpus windows read exactly their planned byte length.** A file that grew
between planning and reading used to overrun its window, so the haystack no longer
matched the offsets the plan computed and matches were reported at wrong positions.
The reader now bounds each file to the remaining window budget and errors with the path
and both byte counts.

**Eigenvectors come back with a canonical sign.** An eigenvector is only defined up to
sign, so the Jacobi rotation accumulation was free to return `v` or `-v`, and a backend
that rounded one rotation differently landed on the opposite one. `jacobi_eigen_body`
now fixes each column so its first component above `EIGENVECTOR_SIGN_EPSILON` is
positive. `symmetric_eigen_jacobi` and `tensor_train_decompose` inherit it. Eigenvalues
and anything invariant to sign are unchanged.

**Two registered ops that no backend had ever executed now have oracles.**
`tensor_train_decompose` shipped without one because a truncated SVD is
basis-dependent; two of the three ambiguities are removed rather than tolerated, and the
remaining oracle is derived analytically. `multi_block_prefix_scan_inclusive_sum` had no
fixture inputs at all.

**The cross-backend parity matrix could not resolve calls.** It never installed the
process-wide dialect lookup, so validation rejected every op carrying an `Expr::Call`
before it reached a backend.

**`docs/INDEX.md` no longer points at documents a published crate does not contain.**
The index gate enumerated the filesystem rather than the tracked set, so 22 deliberately
private documents had been indexed.

**A clean clone now builds its tests.** Thirty-one governance test files embedded a
private operator document with `include_str!`, so `cargo test` failed on any checkout
that did not carry that document. The tests no longer depend on it, and a new suite
(`clean_checkout_build_governance.rs`) fails if any compile-time-embedded file is
absent from the git-tracked set.

**Two release-gate identifiers were wrong.** The dataflow product publishes as
`weirflow`, not `weir`; and `vyre-grammar-gen` was missing from the publish order and
had drifted to 0.6.2. Each now has one owner in `xtask/src/release_train.rs`.

**Release runbooks are runnable again.** `docs/RELEASE.md`,
`docs/RELEASE_CHECKLIST.md`, `docs/RELEASE_ENGINEERING.md`, and `docs/PUBLISH_GATE.md`
cite the real subcommand and the real evidence paths.

**The version-matrix gate no longer requires a document outside this repository.** It
derives the current release-notes path from the release train, so cutting a release
means adding `docs/release/v<version>.md` and nothing else.

**Dependency pins are current.** Every internal pin, eight stale dev-dependency pins,
and the `examples/libs-template` manifest track 0.6.6. Seventeen third-party pins move
to their current patch or minor release; `wgpu`/`naga`, `syn`, and `wide` stay on their
current majors because each of those bumps changes APIs vyre calls directly.

**Repository identity is `santhreal`.** Manifest and documentation links point at the
canonical organisation.

**Private operator state cannot be staged.** `.gitignore` matches operator plans,
status, roadmap, audit, and backlog documents at every depth rather than only at the
repository root.

## Upgrading

The dataflow-import surface named a specific downstream consumer. The API is generic:
it imports alias and reaching-definition facts from any external dataflow engine. Rename
as follows.

| Before | After |
| --- | --- |
| `analyses::weir_alias` | `analyses::alias_import` |
| `analyses::weir_reaching_def` | `analyses::reaching_def_import` |
| `dead_store_with_weir_alias_facts` | `dead_store_with_external_alias_facts` |
| `licm_with_weir_alias_facts` | `licm_with_external_alias_facts` |
| `load_forwarding_with_weir_alias_facts` | `load_forwarding_with_external_alias_facts` |
| `loop_fission_with_weir_alias_facts` | `loop_fission_with_external_alias_facts` |
| `loop_fusion_with_weir_alias_facts` | `loop_fusion_with_external_alias_facts` |
| `security::weir_ifds` | `security::external_ifds` |
| `route_security_taint_through_weir_ifds` | `route_security_taint_through_external_ifds` |
| `security_witness_path_from_weir` | `security_witness_path_from_external_path` |
| `WeirIfdsSecurity{Buffers,Dispatch,RouteError}` | `ExternalIfdsSecurity{Buffers,Dispatch,RouteError}` |
| `WEIR_IFDS_SECURITY_BACKEND_ID` | `EXTERNAL_IFDS_SECURITY_BACKEND_ID` |
| `cfg(feature = "weir_ifds_external_engine")` guard | `cfg(feature = "external_ifds_engine")` guard |

Neither guard names a Cargo feature. `security::external_ifds` bridges to the
external dataflow engine, that engine depends on the vyre platform, and the platform
boundary forbids the platform from depending back on a consumer, so the module cannot
compile in this workspace and the cfg is declared to the compiler rather than to Cargo.
Nothing enables it.

Two data-level renames come with it. The shared fact schema's producer id changes from
`weir` to `external-dataflow`, so a consumer matching on that string in a serialized
fact header updates; the schema version itself is unchanged. In
`rules/security_predicates.toml`, the `weir_mapping` key becomes `external_mapping`
across all ten predicates, so a user who copied that Tier-B file to extend the catalog
updates the key name.

Nothing else in the public API was removed or changed shape. The additions this
release brings, described above, are additive: `Expr::BufferRef` and its builder,
`DispatchConfig::dispatch_grid` and `dispatch_elements`, the grid-sync split
entry points, and the convergence flags. One signature moved:
`transform::inline::default_resolver` now resolves registered composite ops
through the dialect registry instead of returning nothing for every id.
