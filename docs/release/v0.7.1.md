# Vyre 0.7.1 / Weir 0.1.2 release notes

Release train: vyre 0.7.1 and weir 0.1.2. Both release groups move together.

Crates: vyre-driver-cuda@0.7.1 and vyre-driver-wgpu@0.7.1, alongside every other
publishable crate in the vyre group, plus weirflow@0.1.2 in the Weir group.

RC tags: vyre-v0.7.1-rc.1, weir-v0.1.2-rc.1, vyre-0.7.1-weir-0.1.2-rc.1.

Final tags: vyre-v0.7.1, weir-v0.1.2, vyre-0.7.1-weir-0.1.2.

Tag order: cut the three RC tags first, run the release gate against them, then cut
the three final tags. Every tag is product-scoped, so the release workflow does
not use an ambiguous bare `v0.7.1` tag.

## What is in this release

**Public checkouts now reproduce release benchmark source identity.** Runtime
source fingerprints no longer include operator-internal files such as
`AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `SKILL.md`, and `BACKLOG.md`. These files
are present in the private release workspace but are excluded from public crate
and repository surfaces. Their presence or content therefore cannot invalidate
otherwise identical benchmark evidence.

The filter matches whole path basenames. A runtime source such as
`src/AGENTS.md.rs` remains provenance-bearing, and any production source change
still invalidates the benchmark evidence.

**The Weir integration tracks the patch train explicitly.** weirflow 0.1.2 pins
its Vyre dependencies to 0.7.1. This keeps standalone Weir metadata, package
resolution, and the combined release matrix on one dependency-safe train.

## Upgrading

Update every Vyre dependency to 0.7.1 and `weirflow` to 0.1.2. Public APIs are
unchanged. Regenerate benchmark evidence if you maintain custom release proofs,
because the runtime source-tree fingerprint now excludes operator-internal
files.
