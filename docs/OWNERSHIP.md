# Vyre Crate Ownership

This file is generated by `xtask crate-ownership --write` from
`docs/CRATE_OWNERSHIP.toml` and the workspace manifests.

## Boundary rule

Each workspace crate owns one concern and exposes one named seam. Every internal
production dependency crosses the destination's seam, and the interface stated
on that destination's row is what crossing it provides, for every consumer.

## Changing a boundary

1. Change the Cargo manifest.
2. Change `docs/CRATE_OWNERSHIP.toml` when the member set, a layer, a seam, a
   publication class or the curated surface changes.
3. Run `xtask crate-ownership --write`.
4. Add a public import migration test when the curated surface changes.
