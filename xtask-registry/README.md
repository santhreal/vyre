# xtask-registry

xtask subcommands that read the live vyre operation registry.

## Usage

`xtask` builds and runs this binary for the subcommands it assigns here, so the
normal entry point is `cargo xtask <subcommand>`. Running it directly works and
takes the same arguments:

```bash
cargo run -p xtask-registry -- <subcommand> [options]
```

## Why this crate exists

A gate here has to observe something that does not exist in source text: which operations are actually registered, which primitives they compose from, or which rewrite proofs the optimizer submitted. Linking the compiler and the drivers to answer that costs a workspace rebuild, so the gates that read only source text stay in `xtask` and pay none of it.

## Layout

`xtask-registry/src/lib.rs` holds the dispatch table, which is checked against the
subcommands `xtask` assigns to this package. `xtask-registry/src/main.rs` is the
binary `xtask` runs.
